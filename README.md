# RISC-V RV32I CPU Core

A single-cycle **RISC-V RV32I** processor built from scratch in Verilog — full base integer ISA, verified with assembler- and compiler-generated tests, **runs compiled C**, and **deployed to an Intel MAX 10 FPGA**.

## Highlights

- **Full RV32I** (~40 instructions): R/I arithmetic, loads/stores incl. **sub-word access with byte-enable writes**, branches (correct signed/unsigned), `jal`/`jalr`, `lui`/`auipc`.
- **Runs compiled C** end-to-end via the RISC-V GNU toolchain — exercising stack frames, function call/return, loops, and mixed-size memory access.
- **Self-checking verification** against toolchain-generated programs; several real ISA-encoding bugs caught and root-caused (below).
- **FPGA-proven** — synthesized and run on a Terasic DE10-Lite (Intel MAX 10).

## Architecture

```
        ┌─────────┐   ┌──────────┐   ┌─────────┐   ┌──────────┐   ┌───────────┐
  PC ─▶ │  FETCH  │ ▶ │  DECODE  │ ▶ │ EXECUTE │ ▶ │  MEMORY  │ ▶ │ WRITE-BACK│
        │instr_mem│   │ control  │   │   ALU   │   │ data_mem │   │  reg_file │
        └─────────┘   │ reg_file │   │alu_ctrl │   │(byte-en) │   └───────────┘
                      │ imm_gen  │   └─────────┘   └──────────┘
                      └──────────┘
             ▲                                                          │
             └──────────── next-PC logic (PC+4 / branch / jal / jalr) ──┘
```

Harvard architecture (separate instruction/data memories), ~530 lines of RTL across 8 modules: `cpu` (datapath + next-PC/branch/load-store logic), `alu`, `alu_control`, `control`, `imm_gen`, `reg_file`, `instr_mem`, `data_mem`.

## Verification

Rather than eyeballing waveforms, every instruction is checked against **expected register/memory state**, with test programs generated by the RISC-V toolchain (`.s` → ELF → hex) so the machine code is guaranteed correct — no hand-encoding. Compiled C is run end-to-end as a broad real-world check. Per-module testbenches cover the ALU, immediate generator, and memories. Simulated in **Icarus Verilog**; waveforms in **GTKWave**.

## Running Compiled C

```c
int main(void) { int sum = 0; for (int i = 1; i <= 10; i++) sum += i; return sum; }  // 55
```

A minimal startup stub sets the stack pointer, calls `main`, and halts; the result returns in `a0` per the RISC-V ABI. The above yields **`a0 = 0x37 = 55`**, confirming correct ABI, stack frames, loop control flow, and stack-based loads/stores.

```bash
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -nostdlib -nostartfiles -Ttext=0x0 -O0 \
    -o build/prog.elf test/start.s test/main.c
riscv64-unknown-elf-objcopy -O binary build/prog.elf build/prog.bin
python3 scripts/bin2hex.py build/prog.bin > test/prog.hex && make test_cpu
```

## Bugs Found & Fixed

- **`addi` decoded as `sub`** — the R-type funct7 bit (`instr[30]`) was used to pick add/sub for *all* ALU ops, but for I-type `addi` that bit belongs to the immediate; any `addi` with bit 30 set subtracted. Fixed by gating funct7 to R-type (and I-type shifts).
- **Signed/unsigned branches swapped** — `blt/bge` vs `bltu/bgeu` had their `$signed()` casts reversed.
- **`lui` immediate truncation** — a shift inside a concatenation was self-determined to 20 bits and dropped the upper nibbles; fixed with explicit `{instr[31:12], 12'b0}`.
- **Implicit 1-bit wires** — undeclared signals silently became 1-bit nets, truncating 32-bit values; caught by expected-vs-actual register checks.

## Build & Run

```bash
make test_cpu          # compile + run the full-CPU testbench
make test_<module>     # run a single module's testbench (e.g. make test_alu)
make hex PROG=<name>   # assemble test/<name>.s → test/<name>.hex
```
**Requires:** Icarus Verilog, GTKWave, the RISC-V GNU toolchain, Python 3 (Quartus Prime for the FPGA flow).
Project layout: `rtl/` (RTL) · `tb/` (testbenches) · `test/` (programs + hex) · `scripts/` (bin2hex) · `FPGA_MAX10/` (Quartus project) · `docs/`.
